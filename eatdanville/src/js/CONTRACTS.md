# JS module contracts (vanilla ES2020, no build step, no imports)

Every module is a classic script loaded with `defer` after `js/data.js` (which defines `window.EAT_DATA`) and after `hours.js` (`window.EatHours`). Modules must be idempotent IIFEs, attach one global, and never throw when their DOM hooks are absent (a page may not contain them). No third-party network calls except map tiles. No `window.addEventListener('scroll')`. Everything must work with JavaScript that runs before GSAP has loaded (GSAP is optional decoration).

Shared data shape: see `data/schema.md`. `window.EAT_DATA = { site: { corner:{lat,lng,label}, parking:[...], landmarks:[...], walking_note, hashtag, sponsors }, restaurants: [...], categories: [...] }`.
`window.EatHours` API (src/js/hours.js): `now()`, `status(hours, at)`, `statusLine(r, at)`, `isOpen(r, at)`, `closesTonight(r, day)`, `openPast(r, hour, day)`, `tonight(list, day)`, `daypart(at)`, `fmt(minutesOr"HH:MM")`, `toMin("HH:MM")`, `DAYS`.
`window.EatDrawer` (app.js): `open(title, introHtml, itemsHtml)`, `close()`, `resultCard(r, whyText, chipsArray) -> html`, `showCategory(slug)`.
`window.EatToast(msg)`.
Themes: `html[data-theme="light"|"dark"]`; `window.addEventListener('eat:theme', e => e.detail.theme)`. CSS classes and tokens are in `src/css/components.css` and `src/css/tokens.css`; use them, do not add inline styles beyond what is unavoidable.

## search.js -> window.EatSearch
Predictive directory search with an on-device learning model.
- `init()` runs on load: binds every `[data-search]` block (a `.search-box` form with `.search-input[role=combobox]` and a sibling `.search-panel[role=listbox]`). On the `/search/` page (`[data-search][data-page]`) it also renders full results into `#results` and `#results-intro` from `?q=` and re-renders on input.
- Index built from EAT_DATA: restaurants (name, short, cuisine, description, tags, service_notes values), categories (name, alt, keywords, blurb), dishes (name, desc, restaurant), drinks, desserts, services (SERVICE_LABEL names). Add the synonym map from `DESIGN.md`.
- Matching: tokenized prefix match, bigram/trigram similarity, and Damerau-Levenshtein distance <= 2 on tokens of length >= 4. Score = weighted field matches + type prior + time-aware boosts (`EatHours`: open now +, closing soon -, category late_night after 19:00 +, brunch on weekend mornings +) + learned profile boost.
- Suggestions panel: grouped ("Restaurants", "Ways to eat", "Dishes and drinks", "Recent"), max 8 items, each `.search-item[role=option]` with `.thumb` (restaurant card image or the restaurant initial or a category letter), `.t` title with the matched substring wrapped in `<mark>`, `.s` subtitle (status line for restaurants, blurb for categories, restaurant name for dishes), `.k` hint ("Open until 10 PM", "3 of 4", price). Keyboard: ArrowUp/Down move `aria-selected`, Enter activates, Escape closes, Tab closes. Debounce 40 ms. Set `aria-expanded` on the input and `.is-open` on the `.search` wrapper. Empty query shows Recent searches (if any) plus 4 time-aware starters (e.g. at 8 PM: "Late night", "Nightcap", "Open now", "Dessert"). A footer row shows "Suggestions learn from what you tap, only on this device." and a `kbd` hint.
- Activation: restaurant -> navigate to `/r/<slug>/`; category -> `EatDrawer.showCategory(slug)` when on a page with the drawer, else navigate to `/#c=<slug>`; dish/drink -> navigate to `/r/<slug>/#menu`; free text Enter -> navigate to `/search/?q=`.
- Rotating placeholder: cycle through 6 examples every 3.5 s while the input is empty and unfocused (respect `prefers-reduced-motion`: no cycling).
- Learning model: `profile()` returns `{ w: {feature: weight}, n }` from localStorage key `eat.profile.v1`. Features: `r:<slug>`, `c:<service>`, `dp:<daypart>`, `h:<hourBucket>` (buckets: morning, midday, afternoon, evening, late). `learn({type, restaurant, category})` does a bounded online update: w[f] += 0.15 * (1 - w[f]) for touched features, decays all others by 0.98, clamps to [-1, 1], stores n. `rank(list, ctx)` re-orders restaurants by profile affinity (sum of w for r:slug and for the restaurant's true services intersected with ctx.category) and returns a new array. `boost(r)` returns the affinity number used in scoring. `reset()` clears it.
- Recent searches: last 6 committed queries in localStorage `eat.recent.v1`.
- Export: `window.EatSearch = { init, query(text) -> results[], profile, learn, rank, boost, reset, recent }`.

## map.js -> window.EatMap
Leaflet map (vendored at /vendor/leaflet.js, CSS already linked when the page has a map).
- `init()` on load for every `[data-map]` element. Options via data attributes: `data-zoom` (default 17), `data-focus="<slug>"` (open that pin's popup and center on it), `data-full="true"` (bigger, all layers on).
- Tiles: CARTO raster basemaps, `https://{s}.basemaps.cartocdn.com/light_all/{z}/{x}/{y}{r}.png` for light and `.../dark_all/...` for dark, attribution "&copy; OpenStreetMap contributors &copy; CARTO". Swap on `eat:theme`. `maxZoom: 20`, `subdomains: 'abcd'`, `detectRetina` via `{r}`.
- Pins: `L.divIcon({ className: 'eat-pin-wrap', html: '<div class="eat-pin">R</div>', iconSize: [38, 38], iconAnchor: [19, 19] })` for restaurants (letter = `initial`); parking uses `.eat-pin.alt` with a Phosphor car SVG copied from `node_modules/@phosphor-icons/core/assets/regular/car-simple.svg`; landmarks use `.eat-pin.alt` with `map-pin.svg`. Popups use the `.leaflet-popup-content` markup: `<strong>Name</strong>status line<br><a href=/r/slug/>Details</a> · <a reserve>Reserve</a>` (restaurants) or the note (others).
- Layers: `restaurants` (always on), `parking` (on by default), `landmarks` (off by default; on when `data-full`), `loop` (a dashed `L.polyline` connecting the four in order Rancho -> Harvest -> Kaia's -> Incontro -> Rancho, accent color from `getComputedStyle(document.documentElement).getPropertyValue('--accent')`, plus small `.walk-label` divIcon markers at segment midpoints reading "1 min"). Toggle buttons `[data-layer]` with `aria-pressed`.
- `focus(id)`: `id` is a restaurant slug or `parking-<slugified name>`; pans (`flyTo`, 0.8 s) and opens the popup, adds `.is-active` to that pin.
- Fit: on init, `fitBounds` around the four with padding 40 (or center on `data-focus`). Dispatch `window.dispatchEvent(new CustomEvent('eat:map-ready'))` after markers are added. `scrollWheelZoom: false` until the map is clicked (so page scroll is not hijacked); `tap` friendly.
- Export: `window.EatMap = { init, focus, maps: [] }`.

## planner.js -> window.EatPlanner
"Plan my night": a two-stop itinerary from real hours.
- `init()` binds every `[data-planner-controls]` block: chip rows `[data-control="time|mood|prefs|day"]` (prefs is multi-select via `data-multi`). Preset time from `data-preset` (e.g. "19:00" or "20:00"); default day = today; default mood = none; chips reflect state with `aria-pressed`.
- Algorithm `plan({ time, mood, prefs, day }) -> { dinner, nightcap, walkMin, notes }`: candidates = the four restaurants. Dinner must have kitchen open at `time` and for at least 75 minutes after (use `EatHours.spans`). Nightcap must be open (kitchen or bar) at `time + 105 min` for at least 30 minutes and must not equal dinner; prefer restaurants whose `services.late_night` is true and whose bar outlives the kitchen, then the latest close. Mood: `date` favors Incontro and Harvest for dinner and Kaia's or Rancho for the nightcap; `group` favors private_dining true and Kaia's; `solo` favors full_bar and puts the bar-forward places (Kaia's, Rancho, Harvest whiskey) first; `show` (after the Village Theatre) shifts to a single late stop plus dessert. Prefs map to tags: cocktails -> tags include tiki/mezcal/whiskey; dessert -> desserts.length; tequila -> Rancho; wine -> Incontro, Harvest; tiki -> Kaia's; patio -> services.patio. Add `EatSearch.boost(r)` when available. If nothing is open at that time (e.g. 9 PM Monday), degrade gracefully: return the best single stop and a note ("Only Rancho's kitchen is open at 9 on Mondays; make it one long dinner.").
- Render into `#planner-result`: two `.stop` blocks (`.when` with time and small label "Dinner" / "Nightcap", `.what` with `h4` name, `p` reason (why this place for this mood, from nightcap.text or service_notes), `.thumb` image, `.links` chips: Reserve (reservation_url), Menu, Details) separated by a `.walk` row (Phosphor `person-simple-walk` SVG + "1 min across the corner"). Then `.planner-actions`: "Add to calendar" (generates an .ics blob with both stops, download via an `<a download>`), "Copy plan" (clipboard text, then `EatToast('Copied')`), "Share" (Web Share API when available else copy the URL with `?t=19:00&m=date&p=dessert,cocktails&d=fri`). Then `.planner-note` with the honesty line: "Times use each restaurant's posted hours. Reserve to be sure." Dispatch `window.dispatchEvent(new CustomEvent('eat:plan'))` after rendering.
- Read initial state from the URL query (`t`, `m`, `p`, `d`) when present.
- Learning: on any chip change call `EatSearch.learn({ type: 'plan', category: <pref or mood> })` if available; on clicking a stop link the generic `[data-track]` handler in app.js records it, so add `data-track="plan" data-slug="<slug>"` to the stop links.
- Export: `window.EatPlanner = { init, plan, render }`.
